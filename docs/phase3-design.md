## 設定/機敏資訊管理

本版新增以下機敏資訊，需於 `dev-setup` 階段設定管理方式（如 `.env`、環境變數，不得提交進版控）：
- 資料庫連線字串/帳密
- JWT 簽章密鑰（signing secret）

## 跨環境部署影響

本階段不涉及多環境部署設計（留待 `release-handoff`），架構未綁定特定雲端服務，保持一般化。

## 任務清單（票號規則：T-01, T-02, ...，專案無既有編號規則，本版新建）

### 後端

| 票號 | 任務 | 驗收標準 | 依賴 |
|---|---|---|---|
| T-01 | 專案初始化 | Spring Boot 專案可啟動，PostgreSQL 連線成功，Flyway migration 框架就緒 | 無 |
| T-02 | `auth` 模組 | 可透過 `/auth/register`、`/auth/login` 完成註冊與登入，回傳有效 JWT；密碼以 bcrypt 雜湊儲存 | T-01 |
| T-03 | `restaurant` 模組 — CRUD | `/restaurants` CRUD 端點皆可用；編輯/刪除僅限 `createdBy` 本人，非本人操作回 403；刪除為軟刪除（`deletedAt`），不影響他人收藏，已下架餐廳不出現在一般搜尋結果 | T-02 |
| T-04 | `restaurant` 模組 — 文字解析 + 重複偵測 | `/restaurants/parse` 能從貼上文字解析出店名/地址；新增時若與既有餐廳店名+地址高度相似回傳 `duplicateCandidates`（本版防止重複資料的唯一機制） | T-03 |
| T-05 | `favorite` 模組 | `/favorites` 可加入/移除/查詢自己的口袋名單；重複收藏回 409；已下架餐廳仍可在口袋名單查詢到並標示狀態 | T-03 |
| T-06 | `tag` 模組 — 私人標籤 | 私人標籤 CRUD + 套用/移除於 `favorite` 上；同名標籤同一使用者不可重複 | T-05 |
| T-07 | `tag` 模組 — 公開標籤 | `V2__seed_public_tags.sql` 建立初始公開標籤種子資料；`/public-tags` 唯讀查詢；套用/移除關聯 API 僅能操作自己套用的關聯；**不提供新增/編輯/刪除標籤本身的 API** | T-03 |
| T-08 | `note` 模組 | 筆記/評分可 upsert，僅限已收藏的餐廳可建立 | T-05 |
| T-09 | 全站搜尋/篩選 API | `/restaurants` 支援關鍵字 + 公開標籤 + 地區複合查詢，分頁正確 | T-04, T-07（跨模組票，需兩者皆完成） |
| T-10 | 統一錯誤處理 | 所有端點錯誤回應符合 `docs/phase3-api-spec.md` 定義格式，業務錯誤碼涵蓋文件列出的情境 | T-02~T-09 |

### 前端

| 票號 | 任務 | 驗收標準 | 依賴 |
|---|---|---|---|
| T-11 | 專案初始化 | Vue3+TS+Vite 專案可啟動，Vue Router、Pinia、API client 基礎架構就緒 | 無 |
| T-12 | 登入/註冊 + authStore | 可完成註冊、登入，token 存入 `authStore`；route guard 可正確攔截未登入使用者 | T-11, T-02 |
| T-13 | 新增餐廳頁 | 貼上文字可預填欄位、確認後成功送出，重複提示正確顯示 | T-12, T-04 |
| T-14 | 餐廳詳情頁（跨模組票） | 顯示公開標籤，已登入且已收藏時可見私人標籤與筆記入口；收藏/移除收藏可操作 | T-12, T-06, T-07, T-08 |
| T-15 | 搜尋頁 | 關鍵字/標籤/地區篩選可正確查詢並顯示結果列表 | T-12, T-09 |
| T-16 | 地圖元件整合 | `MapView` 可接收餐廳陣列顯示圖釘，點擊圖釘導向詳情頁 | T-15 |
| T-17 | 口袋名單頁 | 顯示自己的收藏，篩選/排序功能正確 | T-12, T-05, T-06 |
| T-18 | 標籤管理頁 | 私人標籤 CRUD 可操作 | T-12, T-06 |
| T-19 | 筆記/評分元件 | 可於詳情頁新增/編輯筆記與評分 | T-14, T-08 |

## 與需求規格的一致性檢查

對照 `docs/phase2-requirements-spec.md` 的 10 項功能與優先排序，上述 19 張票完整覆蓋所有功能，且後端票號 T-02~T-10 對應優先排序 1-10 的資料層/API 依賴順序（如 T-01/T-02 對應優先序 1「註冊/登入」），前端票號 T-12~T-19 對應各頁面所需功能。未發現遺漏或矛盾。

# Requirements Spec — 找餐廳網站

> SDLC Phase 2 產出文件。承接 `docs/product-discovery.md` 的可行方案（方案 A：純網頁版 + 複製文字輔助新增）。

## 1. 功能清單（步驟 6）

| # | 功能 | 說明（可獨立驗收） |
|---|---|---|
| 1 | 註冊/登入 | 使用者可用 Email+密碼建立帳號並登入 |
| 2 | 新增餐廳 | 使用者貼上複製的店名+地址文字 → 系統解析預填欄位 → 確認/修改後儲存進全站共享資料庫 |
| 3 | 私人標籤 | 使用者可建立、編輯、刪除、套用標籤到自己收藏的餐廳，僅自己看得到 |
| 4 | 公開標籤 | 標籤清單由開發者維護，使用者可套用既有公開標籤到任一餐廳，所有使用者都看得到、可用來搜尋 |
| 5 | 口袋名單列表 | 顯示使用者已收藏的餐廳，可依標籤/地區篩選、排序 |
| 6 | 搜尋與篩選 | 在全站餐廳資料庫中，依標籤、城市/區域、關鍵字搜尋 |
| 7 | 地圖檢視 | 在地圖上顯示目前搜尋/篩選結果，可點擊查看詳情 |
| 8 | 餐廳詳情頁 | 顯示店名、地址、公開標籤，若已收藏則顯示個人標籤與筆記 |
| 9 | 個人筆記/評價 | 針對已收藏餐廳寫文字筆記或簡單評分，僅自己看得到 |
| 10 | 編輯/刪除餐廳 | 依權限規則維護餐廳基本資料或個人收藏關聯（詳見下方規格） |

## 2. 範圍界定（步驟 7）

**這一版做**：上述功能 1-10。

**這一版不做**：
- ❌ 串接 Google Places 等付費地圖 API 自動解析地點（維持複製文字+簡單解析）
- ❌ 訂位、外送等交易功能
- ❌ 公開評論系統（僅個人筆記）
- ❌ App、瀏覽器擴充套件、分享功能整合
- ❌ 截圖 OCR 辨識新增餐廳
- ❌ 多人協作/共享口袋名單、好友系統、追蹤他人主頁
- ❌ 餐廳店家端管理後台
- ❌ 重複餐廳的強制去重/合併機制（僅做新增時的相似提示）
- ❌ 忘記密碼、Email 驗證、第三方登入（僅最基本 Email+密碼）

**範圍決定人**：使用者已拍板確認（2026-08-11）。

## 3. 排序後功能清單（步驟 8）

| 順序 | 功能 | 排序理由 |
|---|---|---|
| 1 | 註冊/登入 | 基礎設施，其他功能都依賴帳號存在 |
| 2 | 新增餐廳 | 沒有資料，後面功能無從測試 |
| 3 | 私人標籤 | 核心差異化功能，口袋名單的分類邏輯核心 |
| 4 | 口袋名單列表 | 對應「收藏」情境的主要出口 |
| 5 | 搜尋與篩選 | 對應「查詢」情境的主要出口，核心價值主張 |
| 6 | 餐廳詳情頁 | 承載標籤、筆記的容器頁 |
| 7 | 編輯/刪除餐廳 | 基本資料維護，避免髒資料累積 |
| 8 | 個人筆記/評價 | 提升收藏價值，非核心但重要 |
| 9 | 地圖檢視 | 強化「當下決定吃什麼」情境體驗 |
| 10 | 公開標籤 | 需要一定使用者規模才有意義，且有濫用風險需基本防護，適合等基礎功能穩定後再上 |

## 4. 需求規格書（步驟 9）

### 資料架構前提（關鍵決策）
餐廳資料是**全站共享**的：任一使用者新增的餐廳，其他使用者都能搜尋、瀏覽到。使用者的「口袋名單」是各自獨立的「使用者—餐廳」收藏關聯，多個使用者可以把同一筆餐廳各自加入自己的口袋名單。私人標籤套用在「收藏關聯」上（僅影響自己看到的分類），公開標籤套用在「餐廳本身」上（所有人看到的分類一致）。

### 4.1 註冊/登入
- 使用者可用 Email + 密碼建立帳號；密碼必須雜湊儲存，不得明文儲存
- 登入後以 session 或 token 維持登入狀態
- 瀏覽/搜尋全站餐廳資料庫**不需要**登入；新增餐廳、建立口袋名單、標籤、筆記等個人化操作**需要**登入
- 本版不含忘記密碼、Email 驗證、第三方登入（如 Google 登入）

### 4.2 新增餐廳
- 使用者在「新增餐廳」頁面貼上複製自 Google Maps 或 IG 的文字（含店名、地址等資訊）
- 系統依換行、常見關鍵字規則（如「地址：」、逗號分隔）嘗試解析出店名、地址並預填表單
- 解析結果由使用者確認或手動修改後才儲存；系統不保證解析結果正確
- 必填欄位：店名、地址；選填欄位：分類、備註
- 若貼上內容與資料庫中既有餐廳的店名+地址高度相似，系統提示「可能已存在」，使用者可選擇加入既有餐廳或仍新增一筆（不做強制去重）
- 儲存後該餐廳進入全站共享資料庫，記錄「原始新增者」

### 4.3 私人標籤
- 使用者可在餐廳詳情頁或標籤管理頁建立新標籤（自由文字，如「約會」「一人食」）
- 使用者可將標籤套用到自己收藏的餐廳，一間餐廳可套用多個標籤
- 私人標籤僅建立者本人看得到、可編輯/刪除，其他使用者無法看到或搜尋到
- 刪除標籤 = 從所有套用過的餐廳移除該標籤，不影響餐廳本身或收藏關聯

### 4.4 公開標籤
- 公開標籤清單由**開發者**透過資料庫維護（非使用者建立），使用者**不能**新增或編輯公開標籤本身
- 使用者可從既有公開標籤清單選用，套用到任一餐廳（不限自己新增的餐廳）
- 公開標籤任何人都看得到（含未登入使用者瀏覽時）、都可用來搜尋/篩選
- 使用者只能移除自己套用的標籤關聯，不能移除別人套用的關聯

### 4.5 口袋名單列表
- 顯示目前登入使用者已收藏的所有餐廳（不論是自己新增或加入別人新增的餐廳）
- 可依私人標籤、公開標籤、城市/區域篩選
- 可依加入時間、店名排序
- 每筆項目顯示店名、地址縮寫、已套用標籤

### 4.6 搜尋與篩選
- 提供關鍵字搜尋（比對店名、地址），搜尋範圍為**全站餐廳資料庫**
- 提供依公開標籤、城市/區域篩選的複合條件查詢
- 私人標籤僅能用於篩選使用者自己的口袋名單（因為是個人化資料，對他人餐廳無意義）
- 搜尋結果中，若餐廳已在使用者自己的口袋名單會顯示標記，並可直接「加入口袋名單」

### 4.7 地圖檢視
- 在地圖上顯示目前搜尋/篩選結果（可以是全站搜尋結果，也可以是自己的口袋名單）
- 點擊地圖上的餐廳圖釘可查看該餐廳詳情

### 4.8 餐廳詳情頁
- 顯示店名、地址、公開標籤（所有人看到一致）
- 若使用者已收藏該餐廳，額外顯示自己的私人標籤與筆記，並提供「加入口袋名單」/「移除收藏」按鈕（依目前收藏狀態顯示對應按鈕）

### 4.9 個人筆記/評價
- 僅限已收藏（在口袋名單中）的餐廳可寫筆記
- 筆記為自由文字，可搭配簡單評分（如 1-5 分），僅自己看得到

### 4.10 編輯/刪除餐廳
- 任一使用者都可以「從自己的口袋名單移除」某間餐廳：此動作只影響自己的收藏關聯，不影響餐廳本身或其他人的收藏
- 只有該餐廳的**原始新增者**可以編輯餐廳的店名/地址等基本資料
- 原始新增者刪除餐廳本身時採**軟刪除**（標記為已下架，非實體刪除）：其他使用者已收藏的記錄不受影響，該餐廳會在他們的口袋名單中標示「已下架」；已下架餐廳不會出現在全站搜尋結果中
- 重複資料防治僅依賴 4.2 新增當下的相似度提示；本版不做刪除連動或事後合併機制

### 與問題陳述/商業目標的一致性檢查
對照 `docs/product-discovery.md` 步驟 2：
- 「收藏端痛點」由功能 2（新增餐廳）+ 全站共享資料庫解決：使用者不只能收藏自己新增的餐廳，也能收藏別人已建立的餐廳資料
- 「查詢端痛點」由功能 5（口袋名單）+ 6（搜尋篩選）+ 私人/公開標籤解決：使用者可用自己的分類邏輯整理，也能靠公開標籤篩選到符合條件的餐廳
